## Published guidance and actual checks

The launcher [README](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/README.md) directs ordinary usage support to its Discord and limits technical issues to reports with a clear cause. Its [developer bug template](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/ISSUE_TEMPLATE/bug_report.md) requests macOS, hardware, Wine distribution, and relevant logs; its [feature template](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/ISSUE_TEMPLATE/feature_request.md) requests the problem, solution, alternatives, and context. The [FAQ, questions 11 and 35](https://github.com/yaagl/yet-another-anime-game-launcher/wiki/FAQ) says the project focuses on the original game rather than mod support and distinguishes debuggable software issues from support questions. This supports keeping FPS unlocking out of this proposal; it is not a published decision on native fullscreen.

The Wine distribution [README](https://github.com/yaagl/anime-game-wine/blob/66b9e0e9284c43ccb9d1d546325fb53d63f88128/README.md) explicitly warns that AI-generated slop will be ignored and rejects uninformed Wine issues. It does not specify an AI disclosure form or categorically prohibit every AI-assisted contribution. Recommended response: disclose assistance, provide an understandable small patch and reproducible evidence, identify limitations and who will maintain it, and obtain substantive human understanding/review before submission. Do not claim that compilation, test counts, or this agent's audit constitute human review.

Launcher [PR CI](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/workflows/ci-pr.yaml) runs on `macos-latest` with Node 16/pnpm 7: `pnpm install`, `./configure.sh`, `pnpm exec tsc`, `pnpm run format-check`, and `pnpm run lint`. There is no native fixture job or prescribed test-count threshold. [Main-branch CI](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/workflows/build.yaml) builds/caches Sophon with UV, performs formatting/lint checks, then runs `build-app.js` for seven channels. The [tag workflow](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/workflows/build-ontag.yaml) packages full apps and `resources_*.neu` and creates a draft release. A native addition therefore needs to account for resource-only updates; these workflows do not currently build Wine.

[`configure.sh`](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/configure.sh) prepares generated source/resources and downloads the custom Neutralino runtime/client. [`build-app.js`](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/build-app.js) typechecks, bundles Vite/Neutralino, stages sidecars, writes channel-specific app metadata, and generates a shell entrypoint. A replacement build system is not a contribution requirement.

The overlay [README](https://github.com/riverfog7/macports-wine/blob/0d029255bce8f2f4ac47a1984b59ba82e09d9829/README.md) documents a MacPorts local repository and x86_64 builds on Apple Silicon. Its Portfile selects dependencies, ordered `patchfiles`, x86_64/WoW64 configuration, optional GStreamer, and `install-lib`; on Darwin 24+ it sets deployment target 14.0. It disables Wine's tests in this distribution configuration and installs source license/notices. Neither the matching overlay branch nor current default branch has a Wine build GitHub Actions workflow; the binary repository has none. Focused transition fixtures and build provenance are recommendations needed to evaluate this feature, not pre-existing published CI requirements.

## Recommended unsent channel and decisions

Prepare the short proposal for the launcher's existing [GitHub feature-request channel](https://github.com/yaagl/yet-another-anime-game-launcher/blob/fc56d843461a313fdc5c19af2a2a47eaf8f2f6ac/.github/ISSUE_TEMPLATE/feature_request.md), framed as a concrete technical contribution with the known cause, narrow source patch, fixture evidence, and three maintainer decisions: interest, preferred source/branch, and runtime-release ownership. This is a recommendation based on the published template and technical-issue policy, not a claim that maintainers demand an issue before every PR. The published [Discord](https://discord.gg/HrV52MgSC2) is the alternative if maintainers prefer development discussion there; no specific development room was publicly verified, so none is invented. Do not post to the distribution repository as a support issue, and do not send either draft in this stage.

Prefer distribution-maintained opt-in support if a maintainer agrees to own rebases/builds/releases; keep the launcher disabled/unavailable until an actual identified runtime provides it. The matching Wine 11.0 branch is appropriate for this concrete extraction, but maintainers must decide whether a submission belongs there or should be forward-ported to Wine 11.8/current Wine. The native source patch, a downstream overlay patch, and a launcher option are distinct review units. No published guidance requires full runtime copying/hashing, the fork's FPS supervisor, or its replacement packaging pipeline.
